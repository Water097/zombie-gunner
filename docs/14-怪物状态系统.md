# 14 · 全局共享怪物状态系统

> **为什么要单开一册**：状态不是某个技能的附属品，而是一层基础设施。它决定"跨技能联动"能不能成立。
> **立项动因（用户 2026-10-30 拍板）**：装甲车 20 级「碾过冰冻单位 伤害 +200%」是一条跨技能依赖——装甲车必须能读到干冰弹挂上去的冰冻（02 册 6.2）。没有这一层，这个被动读不到数据，就是一张废卡。
> **阶段定位**：阶段 1-2 完成（13 册"可并行的事"），是阶段 4 demo 的**硬前置**。

---

## 一、不做的代价（先说清楚为什么不能省）

| 做法 | 后果 |
|------|------|
| 每个技能自己维护一份 debuff 表 | 装甲车只认得自己挂的那份冰冻 → 20 级被动实际触发率远低于设计值，玩家判定该卡为废卡 |
| 抗性各自实现 | 装甲兵「减速幅度 x50%」在 A 技能实现了、B 技能漏了 → 同一只怪对两个减速技能体感不一致，05 册图鉴上的抗性说明变成谎言 |
| 易伤写进伤害函数内部 | 11 册「同维度加算 / 跨维度乘算」被破坏，出现无法向玩家解释的双重计算 |

一句话：**跨技能联动的设计价值，取决于状态是不是只有一份。**

## 二、三条设计原则

| # | 原则 | 落地含义 |
|---|------|---------|
| 1 | **单一真相源** | 状态只挂在怪物实体上。技能（乃至未来的主武器加成卡）只能"申请施加"，不许自己存档 |
| 2 | **施加与结算分离** | 来源不知道谁在读，读者不知道谁施加。这正是装甲车能读到干冰弹冰冻的技术原因 |
| 3 | **抗性是打折，不是作废** | 沿用 05 册既定原则（"它还能用，但不够了"）。实现上要求折后系数有下限，不允许归零 |

> 原则 1 的代价是多一层间接调用。但同屏敌人数量有限（04 册蜂群除外），且 06 册已经因为"同屏弹幕翻倍"给加特林设了限制——状态层的开销远低于弹幕层，不值得为省它破坏架构。

## 三、状态清单（全部摘录自现有分册，不自创）

| id | 中文 | 类型 | 主要来源 | 主要读者 | 叠加规则 |
|---|---|---|---|---|---|
| `slow` | 减速 | 幅度 + 时限 | 干冰弹（③ +25%/+2s，局外 12 级至 ~65%）／装甲车（③ +4s）／制导激光（③ 15%）／哨戒机（③ 15%）／燃烧地带（③ 30%）／旋转刀轮（③ 20%） | 一切位移计算；05 册抗性表 | 幅度取最大值，时长按来源各自计时 |
| `freeze` | 冻结 | 时限硬控 | 干冰弹 2 级小冰弹 0.5s → 局外 15 级至 ~1.2s | **装甲车 20 级 +200%**（立项原因）；干冰弹 18 级"冰冻目标受伤 +15%" | 刷新时长，不叠层数（禁止无限续冰） |
| `shock` | 感电 | 幅度 + 时限 | 电磁穿刺（③ 跳电，移速 -20%） | 电磁穿刺 18 级"感电延长" | 幅度取最大值 |
| `burn` | 灼烧 | 每秒伤害 + 时限 | 温压弹（③）／燃烧地带／3.3 暴击卡「灼烧弹头」／06 册「火属性弹头」（每必命中的常驻弱版 DoT） | 伤害结算管线 | 不同来源各算各的实例，可并存（见六节 B 条） |
| `stun` | 眩晕 | 时限硬控 | 燃烧地带局外 15 级：5% 几率 2s | AI 行为树（停止行动） | 眩晕期间免疫新施加的眩晕（防链锁） |
| `knock` | 击退 / 位移 | 一次性 | 装甲车（核心人设）／旋转刀轮 18 级"命中弹开" | 04 册「中线警戒线」判定（装甲车是唯一能把敌人推回警戒线的技能） | 不参与 tick，结算后即清除 |
| `vuln` | 易伤 | 受伤放大 + 时限 | 各技能局内 ④ 维度（温压弹 +25%／干冰弹 +30%／电磁 +20%／装甲车 +20% 等） | 11 册伤害公式的增广区 | **不可叠加**（02 册纪律，写死） |

**冻结 vs 眩晕的区别**（必须存在，否则两个 id 没有意义）：

| | 冻结 | 眩晕 |
|---|---|---|
| 共同点 | 完全停止行动（移动 + 攻击） | 同左 |
| 差异 | **仍可被击退**（冰壳有实体，推得动） | **期间免疫新的眩晕** |
| 为什么这样定 | 保留物理实体感，服务于装甲车"推回警戒线"的人设 | 燃烧地带是区域持续 + 高频 tick + 5% 概率，理论上能把 Boss 锁到死，必须有一条硬防线 |

> 眩晕的防链锁不是可选美化，是必须项：按 06 册加特林约 10 次/秒的 tick 尺度估算，区域内多个目标时每秒要掷几十次判定，5% 概率足以形成长期锁定。

## 四、数据结构与接口（给实现的最小集合）

```
StatusInstance:
  id           : 状态 id（见第三节表）
  magnitude    : 数值（幅度% / 每秒伤害 / 位移距离）
  remainingMs  : 剩余时间（毫秒）
  sourceId     : 施加者（技能 id 或装备词条 id）
  sourceLevel  : 施加者等级（供"XX% 几率 / 延长"类被动判定来源）
  stackPolicy  : MAX_ONLY | REFRESH | INDEPENDENT | NON_STACKABLE
  tags         : [HARD_CC, DOT, DISPLACE, AMPLIFY]  ← 抗性与 UI 按 tag 查，不按 id 查
```

> 时间单位统一毫秒（既定硬性规则第 4 条）。DoT 的"每秒伤害"在进入 tick 时换算为 `perMs = dps / 1000`。

**对外只暴露 7 个函数**（足够覆盖全部现有需求）：

| 函数 | 作用 |
|------|------|
| `apply(enemy, id, magnitude, durationMs, source)` | 施加的唯一入口：内部先过抗性 → 再过叠加策略 → 最后写入。技能不许绕过它 |
| `has(enemy, id) / read(enemy, id)` | 读状态，返回 magnitude 或 0。**装甲车 20 级用 `has(enemy,'freeze')`** |
| `readByTag(enemy, tag)` | 按 tag 批量读（状态图标 / 抗性 UI / 图鉴） |
| `tick(enemy, dtMs)` | 统一递减；`burn` 类在此结算伤害；到期自动移除 |
| `clear(enemy, id) / clearAll(enemy)` | 手动清除 |
| `onDeath(enemy)` | **必须调用**：一次性清空该实体所有状态，防止 DoT 打到已死目标 |
| `snapshot(enemy)` | 给 UI / 图鉴 / 存档（P4 长局可续：读档时按 remainingMs 恢复） |

## 五、施加结算顺序（实现必须严格按此顺序）

```
apply()
  ① 抗性打折   ← 05 册：装甲兵 / 精英 / Boss 各自倍率
  ② 下限保护   ← 折后不得为 0；幅度类地板 = **x0.05**（见八·一）；真正的免疫走 tags 屏蔽，不走乘法器
  ③ 叠加策略   ← MAX_ONLY / REFRESH / INDEPENDENT / NON_STACKABLE
  ④ 写入 Map    ← 唯一真相源
```

**已知抗性表**（摘录 05 册二·七，此处不重新发明）：

| 目标 | 减速 | 击退 | 硬控（眩晕 / 冻结） |
|---|---|---|---|
| 装甲兵 | **幅度 x50%，但时长不打折** | 位移量 x25%；免疫"击飞 / 强制位移"类（普通位移仍生效） | 不免疫 |
| 精英怪 | x40% 基准 | x40% | x40% |
| Boss | **x10%**（04 册：Boss 不免疫控制，只给极低倍率） | x10% | x10% |

> "不许为 0"这条很重要：它既是 05 册"还能用但不够了"的数值实现，也是 UI 能诚实写"抗性：强"而不是"免疫"的前提。

## 六、跨技能交互矩阵（每对都标注 intended / acceptable / bug）

| A | B | 判定 | 说明 |
|---|---|---|---|
| 干冰弹 `freeze` | **装甲车 20 级 +200%** | **intended（立项核心）** | 本册存在的理由。玩家能感知到的教科书级配合：先冻住，再碾过去 |
| 干冰弹 `freeze` | 干冰弹 18 级"冰冻目标受伤 +15%" | intended | 自身闭环，冻结既是控制也是增伤触发器 |
| 多个来源的 `burn` | 并存 | acceptable（设计选择） | 各自独立实例、各自计时。否则"强 DoT 覆盖弱 DoT"会让叠 DoT 变成必选。**注意**：06 册火属性弹头 + 3.3 灼烧弹头 + 燃烧地带三份可共存，是允许的爆发来源，但强度上限已被 06 册 Monte Carlo 锚住 |
| `freeze` 期间被 `knock` | 冻结了还被推走 | acceptable | 见第三节：冻结保留"可被推动"，服务于装甲车推回警戒线的人设 |
| 高频 `stun` 判定 | Boss | 已加防线 | 眩晕期间免疫新眩晕。若实测仍被锁，第一优先调的是免疫窗口，不是降概率 |
| 同一来源重复 `freeze` | 无限续冰 | **bug（用 REFRESH 策略堵住）** | 刷新时长不叠层数，且总时长不得无限增长（上限待定，见第八节） |
| 死亡后仍吃 `burn` | 结算异常 | **bug（用 `onDeath` 堵住）** | 见第四节 |

## 七、失败信号（先定义"坏掉长什么样"，再谈验证）

这一步必须在 demo 之前写好，否则 playtest 等于没做。

| # | 失败信号 | 观测方式 | 说明的问题 |
|---|---|---|---|
| A | 装甲车 20 级 +200% 在**没有冰冻**时也触发 | 日志里 `has(freeze)=false` 却打出 x3 伤害 | 状态层被绕过（技能自己判了冰冻） |
| B | 装甲车 20 级 +200% 在**有冰冻**时**不**触发 | 日志里 `has(freeze)=true` 但伤害未变 | 两份状态不同步（原则 1 被破坏） |
| C | Boss 被长期锁定不动 | 录测 20 秒内 Boss 无位移 | 眩晕防线没生效，或 05 册 x10% 倍率没接入 |
| D | 同一只怪被两个减速技能减速，读数不一致 | 图鉴面板对比 | 抗性在某一路径漏实现 |
| E | 目标死亡后仍跳出灼烧数字 | 视觉观测 | `onDeath` 未调用 |
| F | 读档续玩后状态全丢 / 或残留超期存在 | P4 长局可续流程 | `snapshot` 未写入或未恢复 `remainingMs` |

## 八、可调杠杆与占位符

| 变量 | 当前值 | 类别 | 验证路径 |
|---|---|---|---|
| `freeze` 基础时长 | 0.5s → 局外 15 级至 ~1.2s | 02 册 Excel 派生值 | 阶段 4 实测：1.2s 是否够装甲车走完一次碾压路径 |
| `stun` 触发率 / 时长 | 5% / 2s | 02 册（燃烧地带 15 级自补） | 见失败信号 C；优先调免疫窗口 |
| `slow` 幅度上限 | ~65%（干冰弹局外 12 级） | 02 册自补值 | 建议封顶 80%，再高就接近冻结，两个状态失去区别 |
| **折后系数下限（幅度类）** | **x0.05** | ✅ **2026-10-30 定案** | 只用于 `slow` 幅度 / `vuln` 放大 / `knock` 位移。见八·一 |
| **重复 `freeze` 的处理** | **DR 阶梯 1 / 0.5 / 0.25 / 免疫**，10s 窗口 | ✅ **2026-10-30 定案** | 取代了原先"总时长 ≤2×"的粗放上限。见八·一 |
| `vuln` 与其它增伤是否同源 | 不可叠加（02 册已定） | 已定 | 11 册伤害公式要把增广区与其它乘区分开记账 |

### 八·一 两个占位符的定案（2026-10-30）

**① 折后系数下限 = ×0.05（仅幅度类）**

| 项 | 规则 |
|---|---|
| 生效范围 | `slow` 的幅度、`vuln` 的放大量、`knock` 的位移距离 |
| 为什么是 0.05 | Boss 的抗性已经是 ×0.10（05 册明写"极低倍率"）。下限必须**低于它**，否则会架空 05 册的既定档位 |
| 它的真实身份 | 是**保险丝**，不是常规杠杆——防的是"未来多个抗性倍率连乘后变成 0"。当前没有任何组合会触发它 |
| 排除项 | 装甲兵"免疫击飞 / 强制位移"（05 册）**不是数值归零**，而是 tag 级屏蔽，走 `tags` 过滤、不过乘法器。两者不能混为一谈 |

**② 重复 `freeze` = 递减抗冻结（DR 阶梯）**

同一目标，**自上次冻结结束起 10s 内**，第 n 次冻结的实际时长 = 基础 × (1/2)^(n-1)：

| 第 n 次 | 实际时长（基础 1.2s 时） |
|---|---|
| 1 | 1.2s |
| 2 | 0.6s |
| 3 | 0.3s |
| 4 起 | **免疫** |

- 窗口清零条件：该目标连续 10s 未被冻结。
- 单次窗口内最多连冻 **2.1s ≈ 1.75 倍单次**——自动满足了原方案"总时长 ≤2× 单次"的意图，且**不需要额外维护一个独立上限变量**。
- ⚠️ **重要认知**：按当前数值（干冰弹冷却 ~4.1s、单次 ≤1.2s），**占空比最多约 29%，今天根本触发不到第 2 档**。所以这条是**纯预防性**的：现在加它是零成本、零手感影响，等未来出现第二个冻结来源（比如新的装备词条或局内卡）时才真正生效。**先立规矩，比事后返工便宜。**
- 眩晕**不改用 DR**：它的来源是"区域持续 + 高频 tick + 5% 概率"，DR 窗口挡不住这种密度，所以保留第三节定的更硬的那条——**眩晕期间直接免疫新的眩晕**。两条防线针对两种不同形态的来源，不是重复设计。

## 九、实现顺序（阶段 1-2，且必须在阶段 4 前完成）

| 步 | 内容 | 完成标志 |
|---|---|---|
| 1 | 状态 Map + `apply / read / tick / clear` 四件套 | 单元测试：施加 → tick → 到期自动移除 |
| 2 | 抗性表接入 `apply` 的第 ① 步 | 装甲兵减速减半、时长不减 |
| 3 | `knock` 与 04 册警戒线联动 | 装甲车能把敌人推回警戒线 |
| 4 | **打通 `freeze` → 装甲车 20 级 +200%** | 失败信号 A / B 全绿（**这是本册的验收标准**） |
| 5 | `onDeath` / `snapshot`（支撑 P4 长局可续） | 失败信号 E / F 全绿 |
| 6 | UI：怪物头顶状态图标（按 tag 渲染） | 玩家能看出"这只冻住了，现在该碾过去" |

> **第 4 步是硬门禁**：它绿了，02 册第六节判定为"中高实现难度"的装甲车才算真正落地。
> 本册与 06 册的边界：06 册「火属性弹头」挂的是 `burn`，但它是**主武器层的常驻弱版**；本册只提供容器与规则，不关心来源是哪一层。这正是用户在 3.2.1 拍板的"主武器加成卡与 9 技能互不干扰、但共用同一套状态层"的落地方式。
