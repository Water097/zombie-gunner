# 07 · 局外养成

> 本册定义：关卡之外玩家在攒什么、解锁什么、以及局外攻击加成如何"有界"地给（不再一刀切禁止，见七·五）。

---

## 一、局外做三件事（攻击力可以有，但必须有界）

```
① 解锁内容（新技能、新卡、新武器、新章节）  ← 让"下一局不一样"
② 补生存（要塞血量、减伤、回复）            ← 让"这一关扛得住"
③ 给攻击加成（技能升级奖励 + 装备攻击词条）  ← 养成感来源，但必须框在 ×2.0 内（见七·五）
```

**局外可以给攻击力，但总额框在输出侧上限 ×2.0（七·五）。** 这是整个局外系统的第一条纪律。
（旧版"局外绝不给攻击力"已于 2026-10-30 推翻——它把"技能升级给一点暴击伤害""装备给一点技能系数"这种有界小加成也误伤了。）

理由：这个游戏的全部乐趣在"这一局的 20 次选择"。如果局外能把攻击力**无界**堆到平推，
那么 3 选 1 就退化成"随便点"，卡牌系统当场死亡。
但**有界的小攻击加成**（技能升级给 +0.30%/级 暴击伤害、装备给 +10% 某系伤害）不会杀死 Build——
它只是把起点抬高一点点，杀怪速度的主体仍由这一局的 20 次选择决定。
参考游戏（video(4).mp4）正是这么做的，且运转良好。

武器升级（品级提高个性上限）同样在这个 ×2.0 之内，见 06 册。

---

## 二、五条成长线

| 线 | 资源来源 | 用途 | 上限 |
|----|---------|------|------|
| **玩家等级** | 通关经验（首通多、重复少） | 解锁技能、质变卡、章节 | 有上限（第 1 章封顶） |
| **武器碎片** | 通关掉落 | 解锁新武器 | 武器总数即上限 |
| **装备** | 通关掉落 | 要塞血量 / 减伤 / 回复 / 节奏 / 机会 | **6 个部位**（见 4.2） |
| **道具** | 通关 / 成就 | 解锁道具，装 2 个 | 道具总数即上限 |
| **刷新券** | 通关 / 登录 | 局内重抽一次 | 消耗品，无上限但无积累价值 |

五条线各自独立，互不兑换（除了装备分解成碎片）——避免出现"最优解是刷某一关"的单一通路。

## 三、玩家等级：解锁节奏就是教学节奏

| 玩家等级段 | 解锁 | 这一阶段玩家的体验 |
|-----------|------|------------------|
| 1-3 | 温压弹、干冰弹、电磁穿刺（3 个技能） | 池子浅，20 次选择很容易凑出成型 Build，先让他赢 |
| 4-6 | 装甲车、高能射线、制导激光 | 开始有真正的取舍，阵容变复杂（含持续 / 扫射类） |
| 7-9 | 哨戒机、旋转刀轮、燃烧地带（凑齐 9 个） | 覆盖型技能补齐：对空 / 守线 / 地面封锁 |
| 10+ | 各技能的质变卡逐张解锁 | 老玩家才有的"绝对零度""重型装甲车"级目标；第 2 章后续扩展 |

> 技能总数为 **9**（参考游戏 video(4).mp4 实机确认 6 个：温压弹/干冰弹/电磁穿刺/装甲车/高能射线/制导激光；另 3 个覆盖型技能——哨戒机/旋转刀轮/燃烧地带——为补齐怪物覆盖率由设计补全，待用户确认）。详见 02 册。

**经验规则**：首通给大额，重复通关给小额（防止刷同一关刷到满级）。
**这条不是防沉迷，是防"玩家用最省事的方式跳过内容"。**

## 四、装备系统

### 4.1 为什么压到 6 个部位

| 被否决的做法 | 问题 |
|---|---|
| 装备给**无界**攻击力 | 若某件装备直接给"攻击力 +30%"且不限来源，会压扁 Build（见七·五）。但**有界的攻击词条**（如 +10% 某系伤害、+10% 某技能系数）已被参考游戏验证可行，本期允许，且必须计入 ×2.0 账 |
| 9 个部位 | 9 个**独立加法器**，不是取舍。每次掉落要比 9 个维度，最后每格都填那个公认最优，工作量是 6 个部位的 2-3 倍 |
| 武器放进装备列表 | 武器决定的是**弹道**（打法），其他格子决定的是数字。把武器变成仓库里的一格，玩家就不会再认真选枪了 |

### 4.2 最终方案：6 个部位

原 9 个部位压到 6 个：把「手镯 / 项链 / 戒指」合并为「首饰」，「腿甲」并入胸甲 / 腰带。
**武器独立成系统，不占装备格**（见 06 册）。

| 部位 | 轴 | 给什么（攻击词条已确认，全部进 ×2.0 账） |
|---|---|---|
| **头肩** | 生存/攻击 | 要塞血量；或某系伤害 +X% |
| **胸甲** | 生存/攻击 | 减伤；或攻击 +X |
| **腰带** | 节奏/攻击 | 换弹速度；或某技能系数 +X% |
| **鞋子** | 节奏/攻击 | 道具冷却；或某系伤害 +X% |
| **首饰** | 机会/攻击 | 局内机会（见 4.3）；或某技能系数 +X% |
| **称号** | 规则位 | 修改局内规则（见 4.4） |
| 武器 | — | **独立系统，不占装备格**（见 06 册） |

**每个部位有独立的词条池，池子里可含攻击词条**（参考游戏 video(4).mp4：头盔/护臂/手套均带「攻击 +10 / 各系伤害 +6~8% / 技能伤害系数 +10%」）。
首饰/称号仍是玩法向的（机会/规则），其余 4 个部位以生存/节奏为底、可叠攻击词条。
比例故意偏向"装备不是第二套卡牌系统"——攻击词条只占 ×2.0 的一档，不喧宾夺主。

### 4.2.1 四个部位的词条池（2026-10-30 经验草案，**数值已校准**：MC 聚合 ×1.21 在 ×1.20 内）

"其余 4 个部位"指 **头肩 / 胸甲 / 腰带 / 鞋子**（首饰见 4.3、称号见 4.4，均已定）。
每个部位有**独立的词条池**，池内同时含"轴词条"（该部位的生存/节奏主轴）与"攻击词条"（进 ×2.0 账）。

**设计纪律**：
- 一件装备只带 **1 个词条**（4.5 同部位只能穿 1 件）；玩家掉到轴词条还是攻击词条都"有用"，这是"装备不是第二套卡牌"的关键。
- 攻击词条量级参照 video(4).mp4：**攻击 +10 / 各系伤害 +6~8% / 某技能系数 +10%**，全部计入 ×2.0 的装备档（七·五 ×1.20 总预算内；2026-10-30 Monte Carlo 实测聚合 ×1.21，安全）。
- 强化/镶嵌本期不做（延后），数值预留放大余量。

| 部位 | 轴 | 轴词条（生存/节奏） | 攻击词条（进 ×2.0） |
|---|---|---|---|
| **头肩** | 生存 | 要塞血量 +15% ／ 脱战回复 +30%（更快回血） ／ **要塞生命回复 +X/s（随品级，见下表）** | 火系伤害 +8% ／ 冰系伤害 +6% ／ 物理系伤害 +6% ／ 温压弹系数 +10% |
| **胸甲** | 减伤 | 受到伤害 -8% ／ 对精英&Boss 减伤 -12% | 攻击 +10（全局，进账） ／ 能量系伤害 +8% |
| **腰带** | 节奏 | 换弹速度 +15% ／ 弹夹容量 +20% | 电磁穿刺系数 +10% ／ 电系伤害 +7% ／ 干冰弹系数 +10% |
| **鞋子** | 节奏 | 道具冷却 -15% ／ 重伤急救速度 +25% | 能量系伤害 +8% ／ 高能射线系数 +10% ／ 燃烧地带系数 +10% |

> 攻击词条的分布刻意"偏技能系数 + 偏系"而非"偏通用攻击"——通用攻击 +10 只放在胸甲一处（video 实证允许），其余用"某技能系数 +10%"和"某系伤害 +6~8%"填充，避免一件装备同时压扁 Build。
> 轴词条的"减伤/回复/换弹/冷却"是玩家**能直接感知的生存与节奏改善**，与局内六格卡（主动）形成"被动兜底 vs 主动爆发"的层次，不重叠。

**要塞生命回复（随品级）**：2026-10-30 新增的常驻回血词条，**替代"每波清怪回血"的旧方向**（见 15 册 §七）。
它不依赖清波、战斗内外都生效，是"被动续航兜底"；数值随**装备品级**走：

| 品级 | 回血（血/s） |
|---|---|
| 普通(白) | 2.0 |
| 精良(蓝) | 2.8 |
| 稀有(紫) | 3.6 |
| 史诗(粉) | 4.4 |
| 传说(金) | 5.2 |
| **灾厄** | **6.0** |

> 线性 +0.8/档，白 → 灾厄 3×。具体斜率数值阶段可微调。它与"脱战回复 +30%"是**不同轴**（后者是脱战时的倍率，本词条是常驻绝对量），同一件头肩只带其一。
> ⚠️ **临时基准值**（用户 2026-10-30 确认可暂以此为标，待机器模拟游戏时再校准）：上表 2.0~6.0 的具体斜率与端点均为示例，模拟后按需调整。

⚠️ **装备强化 / 宝石镶嵌本期不做**（用户 2026-10-30 确认延后），但词条数值要预留放大余量：
未来的强化与镶嵌**会进一步增幅这些装备属性**，所以 ×2.0 不能现在就用满，要留一档给后续。

### 4.3 「机会轴」：首饰给的是"可能性"，不是"数字"

首饰也走**攻击词条池**（参考游戏里头盔/护臂/手套都带攻击词条），但只给"这一局你能做什么"的**攻击侧机会**——一件首饰带 1 个词条，词条池如下（具体数值进 ×2.0 账）：

| 词条（示意） | 效果 |
|------------|------|
| **预习** | 开局自动获得 1 个指定技能的入门卡 |
| **审慎** | 每次三选一变成**四选一** |
| **储备** | 本局加成卡配额 +1 |
| **从容** | 第 1 波的敌人密度 -20% |
| **收益** | 本局经验获取 +15% |
| **多谋** | 开局 +1 次刷新 |

**同一件首饰只能选 1 个词条**，所以玩家要选我更需要多一个选项，还是更早成型。

**为什么这样更好**：
- 它符合你的直觉（戴上它，你确实明显更强了）
- 但它兑现战力的地方在**局内的 Build**，而不是局外的加法器
- 它让"攻击类装备"成为**每一局都不一样的东西**（因为每局 Build 不同），而不是一个永远恒定的 +30%

### 4.4 「称号」改做规则修改器

称号不适合做纯数值（它没有掉落感、也不该有）。做成**规则修改器**则几乎是零成本高回报：

| 称号（示意） | 效果 |
|---|---|
| 孤狼 | 装备槽 -1（少穿一件），但局内所有卡效果 +12% |
| 军火商 | 每局武器卡配额 +2，但技能卡配额 -2 |
| 幸存者 | 要塞血量低于 30% 时，全部伤害 +50% |
| 学霸 | 开局额外 +2 次升级，但要塞血量 -25% |
| 莽夫 | 无法手动接管瞄准，伤害 +20% |

**一个称号 = 一条规则**——这是最有性价比的内容扩展方式，几乎不需要美术资源。

### 4.5 掉落与更替

| 项 | 规则 |
|----|------|
| 部位数量 | **6 个**（4 生存/节奏 + 1 首饰 + 1 称号；武器独立不占格） |
| 换装 | 旧装备自动分解为碎片（喂给武器解锁），形成闭环，防止仓库膨胀 |
| 同部位 | 只能穿 1 件 |
| **同一件装备在一个存档里只掉一次** | 防止无限刷同一件然后靠数值碾压（这条比"限量"更重要） |

> **装备的"本期不做什么"**：见 **第六大点**（强化/镶嵌、体力、看广告、抽卡）。
> ⚠️ 2026-10-30 去重：此处原有一个与第六大点完全重复的「为什么不做的四件事」清单，已删除，避免两处各自漂移出不同的说法。

## 五、武器碎片

| 项 | 规则 |
|----|------|
| 掉落 | 每关掉落指定武器的碎片（不同关卡掉不同武器的） |
| 解锁 | 集齐后永久解锁该武器 |
| 溢出 | 已解锁武器的碎片转为通用碎片 |
| 设计意图 | 让"换把枪重新玩一遍"成为长线动力 |

**故意让不同关卡掉不同武器的碎片**：这样玩家想解锁某把枪，就得去打特定的关。
这是唯一一个"重复打旧关卡"的正当理由。

| 不做（本期） | 原因 |

| 装备**强化** / **宝石镶嵌** | 用户 2026-10-30 确认**延后**：本期只做装备词条掉落，强化与镶嵌后续做，但词条要预留放大余量 |

## 七、账号与存档

局外养成一旦有价值（武器、装备、碎片、解锁），纯本地存档就是在裸奔：清个缓存全没了。
所以最终要接数据库。但**踩坑点在架构顺序上，不在技术上**。

### 7.1 先说最大的坑：现在是接库的最坏时机

现在的处境是：

```
玩法还在改（这轮就推翻了 Boss、暴击、技能模型三条）
  + 局外养成的数据结构每天都在变
  + 服务端接口 = 数据结构的固化
  ─────────────────────────────────
  = 每改一次设计，就要改一次"数据库迁移 + API + 前端"
```

**每次 schema 变更的成本比纯前端高一个数量级**，而你还在定玩法的阶段。
我见过太多项目在这里把自己拖死：服务器写完了，玩法却还没定，最后两头都没做好。

### 7.2 建议：加一层，不要直接接

```
存档读写 ──→ SaveAdapter（一个接口，签名固定）
                ├── LocalAdapter    ← 现在用：localStorage
                └── RemoteAdapter   ← 以后用：HTTP + 服务端
```

**本期只实现 LocalAdapter，但所有读写必须走 SaveAdapter，不许直接碰 localStorage。**
这一层大概 50 行代码，但它让你可以在玩法定稿之后用一个下午换实现，而不是重写全部读写点。

### 7.3 存什么 / 不存什么（这条比"用什么数据库"重要)

| 数据 | 存服务端 | 理由 |
|------|---------|------|
| 玩家等级 / 经验 | ✅ | 核心进度 |
| 已解锁的技能与卡 | ✅ | 核心进度 |
| 武器 / 品级 / 碎片 | ✅ | 核心进度 |
| 装备 / 首饰 / 称号 | ✅ | 核心进度 |
| 各关最高记录（是否通关、剩余血量、用时） | ✅ | 有进度清单价值，且可做个人最佳追踪 |
| **每局的详细 Build**（20 次选择、每次的卡） | ❌ | **数据量大、价值低**。除非你要做"这一局的复盘"，否则只存结果 |
| **局内的每帧数据** | ❌ | 同上 |
| 局内波次快照（续局用） | ⚠️ 先本地 | 时效短（几分钟），跨设备续局需求低；但可以存，看你要不要"换设备接着打" |

**判断标准**：只存"删了玩家会心疼的东西"。玩家不会因为"少了一局的详细卡日志"心疼。

### 7.4 离线要不要能玩？

这一条决定整个架构，必须现在定：

| 方案 | 做法 | 代价 |
|------|------|------|
| **A 离线可玩 + 上线同步**（推荐） | 本地先写，联网时增量同步；冲突用"最后写入胜出" | 要处理冲突合并，多写一层约 100-200 行 |
| B 必须联网 | 所有存档实时走 API | 地铁/飞机/弱网直接不能玩。一局 6-7 分钟的游戏，这体验很差 |
| C 纯本地 + 手动导出导入 | 不接库 | 换设备就丢，多端不能同步 |

倾向 **A**：一个 6-7 分钟一局、明确为手机碎片时间设计的游戏，不能联网才能玩。

### 7.5 技术选型

你在这个项目里已经有成熟栈：**Cloudflare D1 + Pages Functions**（已经是 authoritative choice in memory）。
继续用它是最省事的：同一个仓库、同一套部署、没有额外运维。

| 需求 | 选项 | 备注 |
|------|------|------|
| 账号 | 用户名 + 密码（PBKDF2 加盐） | 你已有一套 auth 实现，可直接复用 |
| 数据库 | Cloudflare D1 | 已在用，熟悉 |
| API | Pages Functions（同域，无 CORS） | 已在用 |
| 游客进度 | 允许游客先玩，**登录时把本地进度合并上去** | 重要：不要强制先注册才能玩，这是留存杀手 |

### 7.6 防作弊：自己玩的项目，别在这上面花时间

这个项目是"做来自己学习、自己玩"（你的原话），没有经济系统、没有排行榜、没有 PvP。
所以：**不做服务端校验、不做战绩重放校验、不做 anti-cheat。**

唯一要防的是"手滑改坏数据"——所以 SaveAdapter 层加一个 **写数据时校验版本号** 就够了。

**如果以后要做排行榜**，那才需要服务端重算校验（客户端上报原始输入，服务端算结果）。但现在不要为此付成本。

### 7.7 小结：本期要不要真的搭服务端

建议 **不要**。本期只做 SaveAdapter + LocalAdapter。
理由：

> 这个项目现在最贵的资源不是服务器，是**你验证玩法的时间**。
> 在玩法改动还没收敛之前搭服务端，等于把最贵的资源花在最容易返工的地方。

触发换成 RemoteAdapter 的信号：**当你在连续两周内没有再改动局外数据结构**。

## 七·五、局外强度上限（终稿：输出侧 ≤ ×2.0，且可含攻击力）

### 纪律的演变（重要：早期"局外绝不给攻击力"已推翻）

早期版本定过"局外绝不给攻击力"——这是个**过度反应**。它的本意是防止"局外把攻击堆到平推、局内 20 次选择变走过场"，这点没错；
但它一刀切禁了攻击力，把"技能升级给一点暴击伤害""装备给一点技能系数"这种**有界小加成**也误伤了。

参考游戏（video(4).mp4）明确显示局外给攻击是标准做法：
- 技能升级奖励给「暴击伤害增幅 **+0.30%/级**」（账户级，永久；原 Excel +1.0%，2026-10-30 Monte Carlo 校准后下调，见七·五与 02 册 2.2 之一）
- 装备词条给「攻击 +10 / 干冰弹伤害系数 +10% / 物理系伤害 +6% / 电系伤害 +4% / 能量系伤害 +8% / 电磁穿刺伤害系数 +10%」

**真正危险的从来不是"给攻击"，是"无界地给攻击"。** 所以纪律改为：
> 局外**可以给攻击力**，但总额必须框在下面这条 ×2.0 输出侧上限内。

### 公式（分母写死）

```
局外输出侧上限 = ×2.0   （占比 25%，分母"终局 ×5.0"写死，不随 Build 浮动）
```

### 完整账本：终局 ×5.0 怎么分

```
起始 1.0 → 局外 ×2.0 → 局内 20 次选择 ×2.5 → 终局 ×5.0
```

| 项 | 值 |
|----|-----|
| 局外（输出侧，含攻击） | **×2.0** |
| 局内 20 次选择 | **×2.5**（不打折，完整保留） |
| 终局总倍率 | ×5.0 |
| 局外占比 | **25%**（距 40% 失控线还有一整档余量） |

敌人血量基准维持 ×1.0，不为局外整体上调——配平只针对 ×5.0 这一套尺度。

### 分配建议（四项怎么分这 ×2.0）——【草案，数值阶段需 Monte Carlo 验证】

攻击现在来自四个来源，×2.0 要在它们之间重分（初版草案）：

| 来源 | 建议倍率 | 说明 |
|------|---------|------|
| 武器品级 | ×1.30 | 养成感主来源；**2026-10-30 重分**：独占机制校准后武器总账 = 1.13(基础增长) × 1.153(独占均值 M) = ×1.30（原 ×1.22，腾出的空间给装备档缩到 ×1.20） |
| 玩家等级 | ×1.10 | 主要作用是解锁内容 |
| 技能升级奖励（8/9 技能） | **×1.114**（25% 枪上限） | video 确认的「暴击伤害增幅」类账户级加成。**2026-10-30 Monte Carlo 折算完毕并已拍板：每级 +0.30%**（原 Excel +1.0% 下调） |
| 装备攻击词条 | ×1.20 | video 确认的词条量级；**2026-10-30 Monte Carlo 实测聚合均值 ×1.21（峰值 ×1.28）**，卡在 ×1.20~1.30 预算内，安全 |
| **合计** | **≈ ×1.92** | 卡在 ×2.0 内，留出 ≈0.08 给未来的强化/镶嵌（2026-10-30 独占校准 + 账本重分后） |

> **【技能奖励项 · 2026-10-30 Monte Carlo 已验证，`calibrate-upgrade-reward.mjs`】**
> 它不是乘算项，而是 **`eff = 1 + c × B`**（`c`=枪的暴击率，受 06 册 R1 约束：卡池不给暴击率、现枪 5%~15%、硬上限 25%）。
> - Excel 原值 **+1.0%/级 + 满投资（8 技能×19 级 = 152 次 → B=152%）会超 ×1.15**：精确步枪 ×1.228、未来 25% 枪 **×1.380**。
> - 守 ×1.15 所需的 `B`：15% 枪→100%；**25% 枪→60%**。守 ×1.12：15%→80%；25%→48%。
> - Monte Carlo 另发现两条副作用：① **枪间不平等 3×**（同样的投资，加特林 ×1.030 vs 精确 ×1.090）；② **对虫群几乎无效**（小怪 1~2 发死，暴伤被过杀吃光，实测 eff=1.000），只对 Boss/精英有意义。
> - **✅ 已采纳 +0.30%/级**（2026-10-30 用户拍板）：满投资 B≈46% → 精确步枪 ×1.068、突击 ×1.046、加特林 ×1.023、未来 25% 枪 **×1.114**。理由是本节"要留一档给强化/镶嵌"，靶值从 ×1.15 下调到 ~×1.12。详见 02 册 2.2 之一。

⚠️ 这套分配于 **2026-10-30 完成首轮 Monte Carlo 校准**（`calibrate-gear-exclusives.mjs`）：技能奖励项已由 Monte Carlo 折算（×1.114）；装备攻击词条实测聚合 ×1.21、在 ×1.20 预算内（"6 件叠加速度超预算"的担忧被实测打消）；武器品级经独占机制校准重分为 ×1.30。
"装备叠加速度快、实际占比可能超出"的假设已被证伪——20 万次采样的聚合均值 ×1.2075、峰值 ×1.2826，从未越线。剩余风险仅在"纯单技能双吃元素+系数"极端组合（×1.28，仍在 ×1.30 内）。

### 占 40% 失控线（×2.0 不可动摇的理由）

局内倍率约 ×4-6。
- 局外 **25%（×2.0）** 时：**Build 明显主导，20 次选择决定成败** ← 我们在这里
- 局外 37.5%（×2.5）时：已贴着失控线，"养成感强但 Build 权重下滑"的高风险区
- 局外 **> 40%** 时：会出现"解锁完就平推"——20 次选择变成走过场，"选择 > 深度"作废

**×2.0 不是保守，是把 25% 这档稳稳站住。**

### 一条配套纪律：×2.0 只管"输出侧"

×2.0 管输出侧四件事：**武器品级、玩家等级、技能升级奖励、装备攻击词条**里所有能换成伤害的东西。
生存侧（要塞血量 / 减伤 / 回复）不进这条账，另有一条独立账（数值阶段定），它不改变打法。

⚠️ **装备强化 / 宝石镶嵌本期不做**（用户 2026-10-30 确认延后），但词条数值要预留放大余量：
未来的强化与镶嵌**会进一步增幅这些装备属性**——所以 ×2.0 不能现在就用满，要留一档给后续。
