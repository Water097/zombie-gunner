纪律：一次只改一个类别；若指定某类别里的某一个再具体说。本轮只改整个敌人类别。

### 根因（一句话）
上一版把 8 种敌人全塞进同一条 `hopPose` 骨架，只换颜色和贴片 → 剪影一样、节奏一样、噪点来源也一样。`blob()` 用 8 档硬色阶 + dither 半透明抖出斑驳，眼睛是黑色眼窝方框，装饰全是散落 dot。

### 改法（只改 `src/concept/enemies.mjs`，其它 7 类一行未动）
- **直接复用原库 critters 内核**，不再自己造画刷：`Grid / spring / toss / curve / shift` 从 `vendor/pixelfx/src/fx/critters/_lib.js` 引入。
- **降噪三板斧**（原库「精致」的真实来源）：① `Grid.shade` 主体 `o.a=0.92` → `Grid.draw` 走 `p.blend` 真半透明，**不产生 Bayer 网点**；② 只用 3 档成片色 + 受光锥形 + 1px **方向性描边**（`outline` 左上亮 C[1]、其余暗 C[0]），不是 8 档硬色阶；③ 4 层 `p.glow` 加色底光把硬边缘糊进背景。半透明一律 `blend/disc/glow/glowLine/glowRing`，不用 `p.circle(a<1)/p.line(a<1)/p.ellipse(a<1)`（它们走 dither 会抖网点）。
- 眼睛换成原库竖线眼（随挤压眯/睁/闭/眨/空中看向），去掉黑眼窝方框；亮点只留 2px 窗口反射。
- **灵动**：`curve()` 连续姿态 + 抛物线 `by=-hop*4q(1-q)` + `spring()` 阻尼弹簧余震 + 蓄力 14Hz 微颤；次级运动 = 内部气泡上浮、空中 `sparkle`、4 颗 `toss()` 水滴落地后 `lerp` 爬回本体、back 层水洼与装甲落地 `glowRing`。
- **形状 + 运动分化**：每种独立 `halfW(kind,v,W,t)` 剪影 + 独立 `motion()` 模型。

| 敌人 | 剪影 | 运动 |
|---|---|---|
| 普通 | 圆顶软脚果冻 | 标准弹跳（抛物线 + 弹簧余震 + 水滴爬回） |
| 疾行 | 扁平梭形 + 拖影 | 贴地滑行 + 间歇冲刺，**不跳** |
| 装甲 | 方角硬壳 + 平底 + 横带 | 沉重踏步（几乎不离地，左右摇摆 + 落地余震） |
| 自爆 | 带尖刺球 + 引信 | 原地膨胀脉动，越到周期末越涨大闪白，**不跳** |
| 远程 | 上窄下宽钟形塔 + 底座 | 静置悬浮微动 + 投掷后坐，**不跳** |
| 蜂群 | 3 个极小不规则团 | 各自不同频率 Lissajous 群集乱飞，不整齐不落地 |
| 飞行 | 水母伞盖 + 4 条摆动触须 | 上下漂浮 + 伞缘脉动，不落地 |
| 分裂 | 中间收腰双瓣葫芦 | 左右分裂—合拢（横向），不是纵向跳 |

### 踩的坑（勿再犯）
- `Math.exp(-((v-a)/b) ** 2)` 语法错：一元负号紧邻 `**` 需写成 `Math.exp(-(((v-a)/b) ** 2))`。
- `Grid.ellipse(cx,cy,rx,ry,c,a)` 的颜色函数签名是 `(nx, ny)`，**没有第三个 o 参数**（`Grid.shade` 才有）→ 曾误写 `(nx,ny,o)=>{o.a=1}` 会抛错。
- `Grid.shade` 生成 `body()` 里带 `g.clear()`；蜂群把 3 团叠进同一 Grid 时必须传 `clear=false`，否则只剩最后一团。
- **任何半透明都不要用 Painter 的 `circle/line/ellipse/ring` 的 `a<1`**（它们内部 `put` 走 Bayer dither = 噪点），改用 `disc/blend/glow/glowLine/glowRing`。这是「降噪」最实质的一条。

### 验证
- `node --check` 通过；无头实跑 **8 个敌人 × 40 帧：0 异常 / 0 静默零绘制**。
- Edge 浏览器目视（`#enemies` 锚点，视口截图）：噪点收干净、普通史莱姆靠近原库通透感、8 种剪影一眼可分。

## 第十六轮：8 种史莱姆的死亡效果（用户确认第十五版定稿后追加）

### 需求
「目前这一版本没问题。需要给每个怪物加一个简单的死亡的效果。」纪律不变：一次只改一个类别。

### 设计决策（反馈通道，不是统一一个「啪」）
死亡是 moment-to-moment 循环里的击杀反馈，每种要读出不同信息：
| 敌人 | 死亡 | 读法 |
|---|---|---|
| 普通 | 化水 | 压成水洼 + 4 颗水滴抛物线 + 扩散光环（baseline） |
| 疾行 | 惯性冲散 | 沿滑行方向拉成丝 → 断成 3 段向右飞散 |
| 装甲 | 外壳崩裂 | 4 块圆角方片翻飞 + 内部果冻泄出塌下 |
| 自爆 | **哑弹泄气** | 引信熄灭 → 漏气缩小晃两下 → 一缕烟，**不爆炸** |
| 远程 | 法球坠落 | 头顶法球失控砸地碎裂 + 塔身侧塌 |
| 蜂群 | 逐个啵掉 | 3 团错开 0.14s 依次弹灭，强调数量 |
| 飞行 | 伞盖泄气 | 伞盖变扁、触须收拢、向上飘散（不落地） |
| 分裂 | 两瓣各自化掉 | 中缝裂开 → 左右各自移开缩小（呼应分裂但不生成实体） |

- **自爆不做爆炸是刻意决定**：抵线自爆是炸要塞的，若被击杀时也炸，玩家分不清「我拆弹成功」还是「它炸了」。做成哑弹泄气，让玩家读到前者。这是反馈通道诊断，不是美术偏好。
- 分裂只做「两瓣各自化掉」的视觉，**不生成实体**——逻辑层 `killEnemy` 的分裂是生成子敌人，两条线不混。

### 实现（只改 enemies.mjs + index.mjs 两处，其它 7 类零改动）
- `DEATH` 配置表（8 种 duration 0.62~0.86s，one-shot）+ `softShape(p,cx,cy,rx,ry,c,a,n)` **真半透明超椭圆**（逐点 `p.blend`，n=2 椭圆 / n=5 圆角方），延续上一版降噪纪律：半透明一律不走 `circle/ellipse/poly` 的 a<1（那些 dither 会抖网点）。
- `deathFx()` 8 个分支；通用起手 = 1~2 帧白热 hero frame（`p.disc` + `p.glow`），`A = 1 - smooth(0.64, 0.96, u)`，u≥0.96 直接 return **保证 ending empty**（AUTHORING 契约，可直接 `fx.done()` 回收）。
- `DEATH_EFFECTS` 导出，每个是标准 pure effect `{meta:{loop:false,...}, draw}`，`demoHook` = `killEnemy(type) → createFx(deathModule)`。
- `index.mjs`：import 加 `DEATH_EFFECTS`，CATALOG 新增「敌人类别 · 死亡效果」组（8 张），并更新敌人类别说明为第二版文案。画廊变成 **9 组 57 张**。

### 验证
- `node --check` 通过；8 个死亡 effect：**0 异常 / 有画面 / 全部以空帧结束**；全量回归 **9 组 57 effect / 0 异常**。
- Edge 浏览器目视 `#enemy-death`：8 张都实画出来。
- 调参：初版 `fade=1-smooth(0.50,0.94,u)` 主体停留太短，静态截图常落在淡出末期看着像空格子 → 改成 `smooth(0.64,0.96,u)`，ending empty 仍成立。
- ⚠️ one-shot 循环预览的固有特性：8 个 duration 不同、相位会漂移，静态截图总有 2~3 格落在空档。不是 bug。让用户用画廊的「速度 ×0.5」慢放或「点击单格暂停」定格逐张看。
